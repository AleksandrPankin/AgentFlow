# 06 · Полномочия: владелец и агенты

> Пояснение для человека. Норма — `docs/ai-handoff-protocol.md`, разделы «Product definition», «Owner tasks», «Roles and memory ownership», «Launching workers»; при расхождении прав протокол. Агенты читают этот файл только по прямому запросу. Файл принадлежит шаблону и заменяется при обновлении AgentFlow.

## Кто что делает

| Кто | Что |
|---|---|
| **Владелец** | Даёт смысл: проблема, ценность, приоритеты, границы MVP, бюджет, допустимый риск. Говорит финальное слово: «ок» или «не ок» по документам и по продукту в работе. Делает то, что может только он: ключи, входы, оплата, «да» на прод |
| **Оркестратор** (или сессия без роли) | Пишет документы продукта со слов владельца, проводит гейты, режет срез на задачи, принимает результаты по проверкам, ставит задачи владельцу. Код не пишет |
| **Исполнители** (разработчик, тестировщик, деплоер) | Делают одну задачу в её границах. Документы продукта не правят: предлагают правку в Result (`Proposed spec changes`) |

AI предлагает и критикует, но не выдаёт своё предложение за решение владельца: без ответа владельца элемент остаётся `PROPOSED`, а не `APPROVED`.

## Слово владельца не блокирует

Агенты не ждут ответа молча. Нужен ответ — задача в `state/owner-tasks.md`, работа идёт дальше по рекомендации AI. Поздний ответ «не ок» стоит переделки, и это принято.

## Что блокирует работу

Только эти случаи, и только затронутую работу:

| Случай | Почему ждём |
|---|---|
| Действие, которое может сделать только владелец: ключ, токен, аккаунт, вход, оплата | агент физически не может |
| Выкладка в прод | «да» владельца в сессии проекта платформы |
| Изменение сервера: новая служба, порт, правило прокси или фаервола, роль или права БД, секрет, том, домен | меняет общий контур |
| Деньги сверх бюджета `B06` | решение владельца |
| Новый внешний доступ или персональные данные | риск утечки |
| Необратимое действие без отката | не исправить потом |
| Функция вне `B04` | расширение MVP; ждёт только эта функция, её не строят |

## Задачи на владельца

Файл `state/owner-tasks.md`. Одна задача = одно действие (один секрет = одна задача):

- `OWN-###` — номер не переиспользуется;
- **Сделать** — конкретные шаги: куда зайти, что нажать, какую команду выполнить;
- **Вернуть** — в каком виде нужен ответ: «да / нет», имя, путь, «ключ в `.env`»;
- **Разблокирует** — что ждёт; для финального слова — «ничего — финальное слово»;
- **Когда** — если важен порядок.

Владелец отмечает `[x]` с датой и коротким итогом или отвечает в чате — оркестратор перенесёт. Значения секретов не пишутся ни в файл, ни в чат. Ответы копятся в журнале внизу файла, чтобы не спрашивать дважды; у каждого указан канал: записал сам (`file`) или перенесено из чата дословно (`chat`).

## Формат вопроса владельцу

Вопрос живёт в разделе «Открытые вопросы» своего документа (`Q-V-*`, `Q-B-*`, `Q-P-*`, `Q-T-*`) и задачей `OWN` в очереди:

```markdown
Q-P-003 · [что требует решения, одним предложением]
Затронуто: FR-012, B04
Варианты: A — [...]; B — [...]
Последствия: [цена, срок, качество, безопасность]
Рекомендация AI: [вариант и почему] — по ней работа идёт до ответа
Задача владельцу: OWN-021
```

Молчание — не согласие: без ответа рекомендация остаётся `PROPOSED`.

## Выкладка

- Выкладывает агент сессии проекта платформы, указанного в Project rules (`## Deploy`), по запросу оркестратора.
- Staging — без владельца, если идёт скриптом договора и сервер не меняется.
- Прод — только с «да» владельца в сессии платформы. Оркестратор ставит задачу «да на прод <SHA>»; ждёт только эта выкладка.
