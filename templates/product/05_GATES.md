# 05 · Гейты G0–G5

> Пояснение для человека. Норма — `docs/ai-handoff-protocol.md`, раздел «Product definition»; при расхождении прав протокол. Агенты читают этот файл только по прямому запросу. Файл принадлежит шаблону и заменяется при обновлении AgentFlow.

**Гейт** — проверка готовности среза перед следующим уровнем работы. Срез = Stage из `docs/project-plan.md`. Гейты проводят **агенты**; слово владельца приходит позже через задачу в `state/owner-tasks.md` и работу не останавливает, кроме случаев из списка блокирующего ([06](06_AUTHORITY.md#что-блокирует-работу)).

`tools/gate.py` — другое: автоматические проверки задач (preflight, verify, stage, spec). Гейт G0–G5 использует их как часть проверки, но не равен им.

| Gate | Что готово | Проверяют агенты | Слово владельца |
|---|---|---|---|
| **G0** | Vision | готовность в [01](01_VISION.md) | одна задача на срез: «прочитать 09, ответить ок / правки» |
| **G1** | Brief | готовность в [02](02_BRIEF.md) | та же задача |
| **G2** | PRD среза | готовность в [03](03_PRD.md), `gate.py spec` | та же задача |
| **G3** | Architecture среза | готовность в [04](04_ARCHITECTURE.md), `gate.py spec`, ADR | та же задача |
| **G4** | Реализация среза | `gate.py verify` каждой задачи, тестировщик где нужен, `gate.py stage N` | — (проверка соответствия — работа агентов) |
| **G5** | Ценность в работе | данные по `B07` | задача «проверить срез в боевом применении: ок / не ок и что не так» |

## Как идёт срез

1. Оркестратор готовит или обновляет документы среза, прогоняет готовность G0–G3, пишет [09 Обзор готовности](09_REVIEW.md).
2. Элементы среза получают статус `PROPOSED` — по ним уже можно делать задачи.
3. На владельца ставится одна задача: прочитать 09 и ответить. Разработка идёт параллельно.
4. Ответ «ок» → `APPROVED (OWN-###)` (запись в журнале задач владельца, задача закрыта `[x]`). «Правки» → изменённые элементы, Change Impact ([07](07_DOCUMENT_RULES.md#change-impact)), новые задачи.
5. G4: срез закрывается по проверкам агентов, слово владельца Stage не держит.
6. G5: после выкладки — задача владельцу проверить срез в работе. «Не ок» — новые требования или правки и новые задачи.

## Правила

- Гейт проходится по срезу, а не на весь будущий продукт.
- Критический открытый вопрос из списка блокирующего держит только затронутую функцию; остальное идёт по рекомендации AI со статусом `PROPOSED`.
- Изменение уже проверенного элемента запускает Change Impact.
- Запись гейтов — только в реестре [00_INDEX](00_INDEX.md#реестр-гейтов).
