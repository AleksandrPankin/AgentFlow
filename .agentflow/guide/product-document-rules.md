# Правила документов продукта

> Пояснение для человека. Норма — `.agentflow/protocol.md`, раздел «Product definition»; при расхождении прав протокол. Агенты читают этот файл только по прямому запросу. Файл принадлежит шаблону и заменяется при обновлении AgentFlow.

## Где лежит

```text
docs/product/
  00_INDEX.md            навигация и реестр гейтов
  01_VISION.md           зачем
  02_BRIEF.md            для кого, MVP, границы
  03_PRD.md              FR, NFR, AC
  04_ARCHITECTURE.md     как; список ADR
  09_REVIEW.md           обзор готовности от агента
  decisions/ADR-###.md   технические решения
docs/state/owner-tasks.md     задачи на владельца и журнал его ответов
```

Всё в `docs/` принадлежит проекту: обновление AgentFlow его не трогает. Пояснения для человека (этот файл и соседние `product-*.md`) лежат в `.agentflow/guide/` и заменяются при обновлении.

## Ссылки

1. Brief ссылается на `Vxx`, PRD — на `Bxx` и `SCN`, Architecture — на FR / NFR / AC, `B06` и ADR.
2. Ссылка идёт вниз вверх: AC указывает свой FR (`Source`), FR не перечисляет свои AC.
3. Каждый файл ссылается на `00_INDEX.md`; сеть «каждый на каждого» не нужна.
4. Обратный поиск — по ID: `git grep -n "FR-012" docs/product tasks state`.
5. `docs/state/decisions.md` — решения о процессе и плане; ADR — технические решения продукта. Друг друга не копируют.

## Шапка документа

```yaml
---
id: DOC-PRD
title: "PRD — требования к продукту"
owner: human
author: ai            # кто писал черновик, не кто решает
status: DRAFT         # для Vision и Brief — статус всего документа и потолок для всех элементов
version: 0.1.0        # растёт при каждом изменении смысла
updated_at: 2026-10-09
depends_on: ["02_BRIEF.md"]
---
```

Кто и когда утвердил — не в шапке: ответ владельца лежит в журнале `docs/state/owner-tasks.md`, итог гейта — в реестре `00_INDEX.md`. История изменений — git.

## Формат элементов

Его читает `.agentflow/tools/gate.py`, поэтому он один и тот же везде:

```markdown
### FR-012 — Показать статус задачи
- **Статус:** PROPOSED
- **Source:** B04 / UC-003
- **Формулировка:** При ...
- **Приоритет:** Must

### AC-012 — Статус обновляется после изменения
- **Source:** FR-012
- **Given:** ... **When:** ... **Then:** ...
```

- Статус есть у FR, NFR, ADR. AC наследует худший статус своих FR / NFR.
- Элемент не «готовее» Vision и Brief: пока у любого из них в шапке `DRAFT` или `STALE`, задачи по элементам не запускаются.
- `APPROVED` пишется с задачей владельца, в которой он ответил «ок»: `- **Статус:** APPROVED (OWN-012)`; задача отмечена `[x]`.
- Приоритет у FR и NFR: `Must`, `Should`, `Could`, `Won't` или `Later`. Другое слово — ошибка проверки, а не «не Must».
- UC, UI, SCN, вопросы, риски, гипотезы статуса реализации не имеют.

## Статусы

| Статус | Значение | Можно делать задачи | Кто ставит |
|---|---|---|---|
| `DRAFT` | пишется, может быть неполным | нет | AI |
| `PROPOSED` | агент проверил, вопрос владельцу поставлен | да | оркестратор после проверки гейта |
| `APPROVED (OWN-###)` | владелец сказал «ок» | да | оркестратор, только по записи в журнале владельца |
| `STALE` | источник изменился, нужна перепроверка | нет | Change Impact |
| `SUPERSEDED` | заменён новым элементом или версией | нет | оркестратор |

Выход из `STALE`: перепроверка → `PROPOSED`; владелец оставил как есть → `APPROVED`; заменён → `SUPERSEDED`. `OPEN` — только у вопросов, рисков и гипотез.

## Change Impact

Когда меняется элемент, по которому уже можно работать:

1. Записать, что меняется и зачем; поднять `version` в шапке.
2. Найти зависимых: `git grep -n "<ID>" docs/product tasks state`.
3. Зависимым элементам — `STALE`.
4. Открытые задачи, которые их называют, — `blocked` в реестре с пометкой `spec changed <ID>`. Принятые задачи не трогать; нужна переделка — новая задача.
5. Если меняется смысл, границы или что-то из списка блокирующего — задача владельцу.

`APPROVED` не переписывается без следа: новая версия и новый вопрос владельцу по затронутой части.

## Проверка

`python .agentflow/tools/gate.py spec`: дубли ID, неверные статусы и приоритеты, Must FR без AC, AC без FR, `APPROVED` без закрытой задачи владельца, элемент «готовее» Vision или Brief, сводка статусов. Перед каждым гейтом — без ошибок.

Код проверяет только ID, латинские статусы и отметку `[x]`. Что именно ответил владелец и покрывает ли AC свой FR — проверяет оркестратор при гейте и владелец.

Оглавление продукта: `docs/product/00_INDEX.md`.
