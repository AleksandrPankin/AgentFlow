# Инструкция: как пользоваться AgentFlow

Шаблон памяти проекта с командой агентов: оркестратор, разработчик, тестировщик, деплоер. Как это устроено внутри — протокол `.agentflow/protocol.md`. Здесь только «что сказать и что проверить».

Шаблон — папка, куда склонирован репозиторий AgentFlow. Ниже она обозначена `<AgentFlow>`: подставь свой путь.

Нужно на машине: git, Python 3, PowerShell 7, и те CLI, которыми будут работать исполнители (`codex`, `claude`, `agy`).

## Как устроен проект с AgentFlow

```
проект/
├─ AGENTS.md, CLAUDE.md   AgentFlow владеет только блоком между метками agentflow:start и agentflow:end
├─ .claude/commands/      пять команд AgentFlow
├─ .agentflow/            механизм: одинаков во всех проектах, обновление заменяет папку целиком
├─ docs/                  знание проекта: product/ → plan.md → tasks/ → state/ → runbook/;
│                         обновление его не трогает
└─ код проекта
```

# Часть 1. Установка и обновление

Установку делает сессия LLM: она читает файлы проекта и сливает их, а не копирует поверх. Скрипта нет. Процедура — `<AgentFlow>\.agentflow\install.md`; в Claude Code её запускает скилл `integrate-agentflow`.

## Что сказать

Открой папку проекта, запусти Claude Code и скажи (подставь пути):

```text
Внедри AgentFlow из <AgentFlow>.
Worktrees folder: <D:\tmp>.
Product definition: yes.
Deploy: platform project <D:\OneDrive\AI\04_Infra_PVE>.
```

- Строку «Product definition» оставь, если нужно описать продукт: Vision, Brief, PRD, Architecture ([Шаг 0](#шаг-0-продукт-до-разработки-по-желанию)). Если описание уже есть в проекте (например, папка `00_PRD/`), сессия перенесёт его в `docs/product/`.
- Строку «Deploy» оставь, если проект выкладывается на сервер.
- В Codex или другом инструменте: `Follow <AgentFlow>\.agentflow\install.md for this project.` и те же строки.

Сессия сама определит режим:

| Что в проекте | Режим |
|---|---|
| пусто | новый проект |
| живой проект без AgentFlow | внедрение в начатый проект |
| AgentFlow 2.x (`docs/ai-handoff-protocol.md`, `state/`, `tasks/` в корне) | перенос на устройство 3.0 |
| `.agentflow/` старой версии | обновление |
| та же версия, но заглушки или пропуски | ремонт |

## Что будет дальше

1. Сессия читает проект и показывает план: что заменит, что перенесёт, что создаст, что оставит как есть. Ничего не меняет.
2. Ты отвечаешь «ок» или правишь план.
3. Сессия выполняет план и показывает изменения (`git diff`).
4. Ты проверяешь и говоришь «коммить». Один коммит; откатить — `git revert`.

Вопросы, на которые сессия не нашла ответа в проекте, она ставит тебе задачами в `docs/state/owner-tasks.md`, а в файлах оставляет пометку со ссылкой на задачу.

Ожидаемый результат: в `AGENTS.md` есть блок AgentFlow со строкой `AgentFlow version`, папка `.agentflow/` на месте, `docs/state/` и `docs/plan.md` описывают реальное состояние проекта, `python .agentflow/tools/ledger.py show` работает. Текст проекта вне блоков AgentFlow не изменён. Если сессия сказала, что тестовый конфиг может уйти на staging или прод, — это задача на исправление до начала работы.

## Один раз: проверить инструменты

Командная строка каждого CLI в `.agentflow/tools/run-task.ps1` (таблица `$Tools`) — значения по умолчанию. Перед первой настоящей работой проверь каждый инструмент пустяковой задачей. Качество модели не проверяется, только запуск.

1. Попроси оркестратора: «Сделай проверочную задачу T-000 для developer: прочитать README.md и записать в Result его первую строку, без коммита кода».
2. Запусти её по очереди в каждом инструменте:

```powershell
.agentflow\tools\run-task.ps1 T-000 codex
.agentflow\tools\run-task.ps1 -Status
```

После каждого прогона: `.agentflow\tools\run-task.ps1 T-000 -Stop`, затем следующий (`claude`, `agy`).

Для каждого инструмента должно быть:

| Проверка | Как видно |
|---|---|
| Окно открылось и видно работу | глазами |
| Prompt дошёл, роль и задача прочитаны | в окне / в `docs\tasks\.runtime\T-000.<n>.log` |
| Рабочая папка — worktree задачи | агент пишет её в Result или видно в окне |
| `## Result` записан в `docs\tasks\T-000-*.md` основной папки | открыть файл |
| `-Status`: `exited`, exit 0 (окно интерактивного `agy` закрывает `-Wait`, когда Result заполнен) | `.agentflow\tools\run-task.ps1 -Status` |
| `-Wait` вернул одну строку `T-000 finished: ...` | `.agentflow\tools\run-task.ps1 -Wait T-000 -PollSec 5` |
| `agy` не спросил «доверять ли папке» | глазами в его окне |

Что-то не сошлось — поправь строку инструмента в `$Tools` и повтори. Путь к codex и его постоянные аргументы на этой машине задаются переменными окружения `AGENTFLOW_CODEX` и `AGENTFLOW_CODEX_ARGS`, а не правкой `$Tools`. После проверки попроси оркестратора убрать T-000 (`cancelled`, worktree и ветку удалить).

# Часть 2. Работа каждый день

## Как это работает

```text
Ты: цель + лимиты ──> Оркестратор: план ──> Ты: «ок»
                         │
                         ▼
        Оркестратор сам, без тебя:
          запускает все задачи, которые можно делать параллельно
          ждёт их окончания (.agentflow\tools\run-task.ps1 -Wait, без токенов)
          принимает результаты, сливает ветки
          сразу запускает следующие
                         │
                         ▼
        Вопросы к тебе копятся в docs/state/owner-tasks.md — работа их не ждёт.
        Ждёт тебя только: ключ / вход / оплата, «да» на прод, изменение
        сервера, деньги сверх бюджета, новый внешний доступ, необратимое,
        функция вне MVP
```

- **Оркестратор** — одна сессия Claude Code (при нехватке лимита Claude — Codex). С ним ты разговариваешь. Сам код не пишет.
- **Исполнители** — отдельные видимые окна, по одному на задачу. Их открывает оркестратор через `.agentflow\tools\run-task.ps1`. Ты окна не открываешь и строки запуска не вставляешь.
- Всё общение идёт через файлы: задача — `docs/tasks/T-NNN-*.md`, результат исполнитель пишет в конец этого же файла.

## Шаг 0. Продукт до разработки (по желанию)

Если в проекте есть `docs/product/`, агенты строят только то, что там описано, и ссылаются на ID требований.

1. Расскажи оркестратору (или сессии без роли), что за продукт: проблема, для кого, что должно получиться. Можно дать заметки и исследования.
2. Он запишет Vision, Brief, PRD и Architecture для первого среза, проверит их (`python .agentflow/tools/gate.py spec`) и напишет короткий обзор `docs/product/09_REVIEW.md`: что ясно, чего не хватает, что упрощено.
3. На тебя появится задача «прочитать 09 и ответить». Разработка в это время уже идёт: элементы в статусе `PROPOSED` можно делать.
4. Ответил «ок» — элементы становятся `APPROVED (OWN-###)`, со ссылкой на твою задачу. Ответил правками — оркестратор меняет документы и задачи.

Как это устроено, для тебя: `.agentflow/guide/product-*.md` (гейты, полномочия, правила, пример). Агенты эти файлы не читают.

## Задачи на тебя

Всё, что можешь сделать только ты, оркестратор пишет в `docs/state/owner-tasks.md`: что сделать → что вернуть → что это разблокирует. Задачи копятся; бери их, когда есть время. Закрыть задачу: поставь `[x]`, дату и короткий итог, или ответь оркестратору в чате — он перенесёт. Ключи и пароли в файл и в чат не пиши: только в `.env`.

Твоё финальное слово — тоже задачи: «проверить документы среза» и «проверить срез в работе». «Не ок» — нормальный ответ: оркестратор заведёт правки.

## Шаг 1. Запустить оркестратора

VS Code → открыть папку проекта → новая сессия Claude Code → ввести:

```text
/start-role orchestrator
Цель: <что хочешь получить>.
Лимиты: Claude — <много/мало>, Codex — <…>, Antigravity — <…>.
```

Строку «Лимиты» можно пропустить — тогда оркестратор спросит. Кто выкладывает, записано в правилах проекта (`## Deploy`).

Ожидаемый результат: оркестратор пересказывает, где проект сейчас, и предлагает план: задачи, роли, инструменты и какие задачи пойдут параллельно.

## Шаг 2. Утвердить план

Прочитай план. Ответь «ок» или поправь его: «T-102 не нужна», «тестировщик через Antigravity» и т.п.

У каждой задачи разработчика есть уровень риска — во что обойдётся её ошибка:

- `low` — ошибка видна сразу и легко откатывается; тестировщик не обязателен.
- `risky` — ошибку увидят пользователи, или она незаметна; задачу проверяет тестировщик, и он убеждается, что тесты падают без изменения.
- `critical` — деньги, доступы, данные или необратимое действие; сначала отдельная задача на другом инструменте пишет приёмочный тест, потом задача на функцию, которой этот тест менять нельзя.

Не согласен с уровнем — поправь его в ответе на план.

Ожидаемый результат: оркестратор пишет файлы задач, запускает все независимые задачи сразу, открываются окна исполнителей.

## Шаг 3. Не мешать

Оркестратор работает сам: следит за окнами, принимает результаты, запускает следующие задачи, переводит задачу на другой инструмент, если кончился лимит.

Окна исполнителей можно смотреть, но не закрывать: закрытое окно = оборванная задача. Окно закрывается само, когда исполнитель закончил; окно `agy` закрывает оркестратор, как только исполнитель заполнил Result.

Оркестратор просыпается сам, когда исполнитель закончил. Пока исполнители работают, у него запущена фоновая команда `.agentflow\tools\run-task.ps1 -Wait`: она ждёт без расхода токенов и будит его одной строкой. Поэтому не закрывай сессию оркестратора, пока работают исполнители: закрытая сессия не проснётся, и готовые задачи будут ждать до следующего `/start-role orchestrator`.

Отвечай, когда удобно:

- задачи в `docs/state/owner-tasks.md` — по мере времени;
- исполнитель — войти в систему (прямо в его окне);
- деплоер — «да» на прод (в сессии проекта платформы).

## Шаг 4. Выкладка на сервер

Выкладывает агент в сессии проекта платформы (например, 04), указанного в правилах проекта (`## Deploy`). Оркестратор сам готовит задачу выкладки, пишет запрос в `docs/infra-requests.md` и сообщает сессии платформы. Staging выкладывается без тебя, если сервер не меняется. Для прода деплоер спросит твоё «да» в своей сессии, показав commit и окружение; оркестратор поставит тебе задачу «да на прод». Без «да» на прод не пойдёт, остальная работа при этом идёт.

## Шаг 5. Закрыть день

В чате оркестратора:

```text
/update-memory
/handoff-cmd
```

Ожидаемый результат: `docs/state/handoff.md`, `docs/state/current-step.md` и `docs/tasks/tasks.md` обновлены, `handoff.md` и `current-step.md` короткие (1–2 экрана). Сессии можно закрывать.

На следующий день — снова шаг 1. Новый оркестратор продолжит с того места, где остановился прошлый.

## Дашборд

Дашборд — твой инструмент, не агентов: таблица задач, фильтры, Гант, канбан по статусам, сроки и связи между задачами. Он только читает `docs/tasks/tasks.md`, `docs/tasks/T-*.md` и git и ничего не меняет.

1. Запусти сервер: `python .agentflow\dashboard\serve.py`. Он сам соберёт страницы и откроет браузер на `http://127.0.0.1:8765`. Кнопка ↻ в шапке (между «Собрано …» и темой) пересобирает обе страницы целиком и обновляет текущую.
2. Без сервера: `python .agentflow\dashboard\build.py`, затем открой файл `.agentflow\dashboard\out\index.html` (обзор) или `.agentflow\dashboard\out\graph.html` (Гант и сроки). Кнопка ↻ в этом режиме неактивна.
3. Дашборд обновляется только по запросу: кнопка, команда или просьба оркестратору («пересобери дашборд»). Сам он ничего не пересобирает, поэтому без запроса данные могут отставать. Страницы лежат вне git.
4. Хочешь поправить дашборд — дай задачу с описанием правки. Перед правкой: `python .agentflow\dashboard\snapshot.py save "что меняем"`; откат: `python .agentflow\dashboard\snapshot.py restore vN`. Правила интерфейса: `.agentflow\dashboard\UI-RULES.md`.

Интерфейс русский (он для человека); статусы реестра (`ready`, `review`, `done`…) показаны русскими метками: В очереди, На приёмке, Принята и так далее.

## Какая модель делает задачу

Оркестратор ставит в каждой задаче уровень, а не модель: `Model: small | standard | strong` и `Effort:` (сколько думать). Дешёвый уровень идёт на механику, сильный — на тестера рискованных изменений и код, где ошибка тихая и дорогая. Что значит каждый уровень для Claude, Codex и agy, записано в одной таблице `.agentflow\tools\models.json`. Вышла новая модель — меняется только эта таблица. На одной машине уровень можно переопределить переменной окружения, например `AGENTFLOW_MODEL_CLAUDE_STRONG=claude-fable-5-1`. Какая модель отработала, видно в строке запуска и в `.agentflow\tools\run-task.ps1 -Status`. Последний упор в лимит по каждому инструменту — `.agentflow\tools\run-task.ps1 -Limits`.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Исполнитель написал `blocked` | Ничего: оркестратор увидит сам. Если вопрос к тебе — он спросит |
| Кончился лимит у инструмента | Ничего: оркестратор переведёт задачу на запасной инструмент |
| Окно исполнителя закрылось | Ничего: закончил — `-Status` покажет `exited` или `error`; оборвалось — `dead`, оркестратор продолжит с последнего commit или начнёт заново |
| Исполнитель завис | Скажи оркестратору «T-101 висит». Он остановит его (`.agentflow\tools\run-task.ps1 T-101 -Stop`) и перезапустит |
| Оркестратор просит тебя написать «дальше» или закрыть окно | Это ошибка оркестратора: напомни про `.agentflow\tools\run-task.ps1 -Wait` |
| Окно `agy` осталось открытым после Result | Строка `-Wait` скажет почему (в worktree есть незакоммиченное); решает оркестратор: `-Stop` или новая попытка |
| Ошибка «another run-task.ps1 launch is in progress» | Подожди минуту и повтори: идёт другой запуск |
| Задача в Antigravity (IDE) | Оркестратор готовит её (`-Manual`) и пишет папку и промпт; запускаешь ты; когда закончится — `.agentflow\tools\run-task.ps1 T-NNN -MarkFinished` |
| Задача не запускается: «Spec ... is DRAFT» или «not found» | Требование ещё не проверено или не существует. Оркестратор проверяет документы или исправляет `Spec:` в задаче |
| Простая задача, команда не нужна | Работай без роли: `/start-session` в начале, `/update-memory` в конце |

## Шпаргалка

| Что | Команда |
|---|---|
| Начать работу (оркестратор) | `/start-role orchestrator` + цель + лимиты |
| Задачи на тебя | `docs/state/owner-tasks.md` |
| Проверить документы продукта | `python .agentflow\tools\gate.py spec` |
| Что сейчас работает | `.agentflow\tools\run-task.ps1 -Status` |
| Остановить зависшего исполнителя | `.agentflow\tools\run-task.ps1 T-NNN -Stop` |
| Дождаться, пока исполнитель закончит | `.agentflow\tools\run-task.ps1 -Wait` |
| Где упёрлись в лимит | `.agentflow\tools\run-task.ps1 -Limits` |
| Запустить задачу вручную | `.agentflow\tools\run-task.ps1 T-NNN <codex\|claude\|agy>` |
| Таблица задач | `python .agentflow\tools\ledger.py show` |
| Дашборд (обзор, Гант, канбан) | `python .agentflow\dashboard\serve.py`, кнопка ↻ обновляет |
| Закрыть день | `/update-memory`, затем `/handoff-cmd` |
| Работа без команды | `/start-session` … `/update-memory` |
