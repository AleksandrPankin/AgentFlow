# Инструкция: как пользоваться AgentFlow

Шаблон памяти проекта с командой агентов: оркестратор, разработчик, тестировщик, деплоер. Как это устроено внутри — [README](README.md) и [протокол](docs/ai-handoff-protocol.md). Здесь только «что нажать и что ввести».

Шаблон — папка, куда склонирован этот репозиторий. Ниже она обозначена `<AgentFlow>`: подставь свой путь. Какие файлы шаблона попадают в проект, а какие нет, — в протоколе, раздел «Installing or updating AgentFlow».

Нужно на машине: git, Python 3, PowerShell 7, и те CLI, которыми будут работать исполнители (`codex`, `claude`, `agy`).

# Часть 1. Установка

| Что в папке проекта | Вариант |
|---|---|
| Пусто, или форк / чужой код без памяти | [А. Новый проект](#а-новый-проект) |
| Уже есть память (`docs/ai-handoff-protocol.md`, `state/handoff.md`) | [Б. Проект с памятью](#б-проект-с-памятью) |

## А. Новый проект

### Шаг 1. Git

Агентам нужен git с основной веткой и хотя бы одним коммитом: разработчики работают в отдельных папках-worktree от основной ветки.

Пустая папка:

```powershell
cd D:\путь\к\проекту
git init -b main
git commit --allow-empty -m "init"
```

Форк: git уже есть. Основная ветка — `git branch --show-current` (`main` или `master`).

### Шаг 2. Установить шаблон

Открой папку проекта в VS Code, запусти Claude Code и введи (подставь путь и папку для worktree — вне проекта и вне OneDrive):

```text
Install AgentFlow from <AgentFlow> into this project:
<AgentFlow>\docs\ai-handoff-protocol.md, section "Installing or updating AgentFlow", "Install".
Worktrees folder: <D:\tmp>.
```

Ожидаемый результат: в проекте есть `AGENTS.md` (со строкой `AgentFlow version`), `roles/`, `tools/`, `state/`, `docs/project-plan.md` с реальными этапами проекта; `python tools/ledger.py show` работает; один commit. Если Claude сказал, что тестовый конфиг может уйти на staging или прод, — это задача на исправление до начала работы.

## Б. Проект с памятью

Память уже есть: обычная или командная прошлой версии. Её нужно обновить, ничего не потеряв.

```text
Update AgentFlow in this project from <AgentFlow>:
<AgentFlow>\docs\ai-handoff-protocol.md, section "Installing or updating AgentFlow", "Update".
```

Если память лежит не в корне проекта, а в соседней папке, добавь первой строкой: `Project memory is in <путь>; move it to the project root first.`

Claude покажет список правил проекта, которые нужно перенести в `## Project rules`. Проверь его и ответь «ок».

Ожидаемый результат: версия в `AGENTS.md` совпадает с шаблоном, старые handoff, decisions и known-issues на месте, в `decisions.md` есть запись о переходе, один commit.

## В. Один раз: проверить инструменты

Командная строка каждого CLI в `tools/run-task.ps1` (таблица `$Tools`) — значения по умолчанию. Перед первой настоящей работой проверь каждый инструмент пустяковой задачей. Качество модели не проверяется, только запуск.

1. Попроси оркестратора: «Сделай проверочную задачу T-000 для developer: прочитать README.md и записать в Result его первую строку, без коммита кода».
2. Запусти её по очереди в каждом инструменте:

```powershell
tools\run-task.ps1 T-000 codex
tools\run-task.ps1 -Status
```

После каждого прогона: `tools\run-task.ps1 T-000 -Stop`, затем следующий (`claude`, `agy`).

Для каждого инструмента должно быть:

| Проверка | Как видно |
|---|---|
| Окно открылось и видно работу | глазами |
| Prompt дошёл, роль и задача прочитаны | в окне / в `tasks\.runtime\T-000.<n>.log` |
| Рабочая папка — worktree задачи | агент пишет её в Result или видно в окне |
| `## Result` записан в `tasks\T-000-*.md` основной папки | открыть файл |
| `-Status`: `exited`, exit 0 (интерактивный `agy` — `running`, пока окно открыто) | `tools\run-task.ps1 -Status` |

Что-то не сошлось — поправь строку инструмента в `$Tools` и повтори. Путь к codex и его постоянные аргументы на этой машине задаются переменными окружения `AGENTFLOW_CODEX` и `AGENTFLOW_CODEX_ARGS`, а не правкой `$Tools`. После проверки попроси оркестратора убрать T-000 (`cancelled`, worktree и ветку удалить).

# Часть 2. Работа каждый день

## Как это работает

```text
Ты: цель + лимиты ──> Оркестратор: план ──> Ты: «ок»
                         │
                         ▼
        Оркестратор сам, без тебя:
          запускает все задачи, которые можно делать параллельно
          следит за ними (tools\run-task.ps1 -Status)
          принимает результаты, сливает ветки
          сразу запускает следующие
                         │
                         ▼
        Ты нужен только для: входа в систему, решения по архитектуре,
        опасного действия, «да» на выкладку в прод
```

- **Оркестратор** — одна сессия Claude Code (при нехватке лимита Claude — Codex). С ним ты разговариваешь. Сам код не пишет.
- **Исполнители** — отдельные видимые окна, по одному на задачу. Их открывает оркестратор через `tools\run-task.ps1`. Ты окна не открываешь и строки запуска не вставляешь.
- Всё общение идёт через файлы: задача — `tasks/T-NNN-*.md`, результат исполнитель пишет в конец этого же файла.

## Шаг 1. Запустить оркестратора

VS Code → открыть папку проекта → новая сессия Claude Code → ввести:

```text
/start-role orchestrator
Цель: <что хочешь получить>.
Лимиты: Claude — <много/мало>, Codex — <…>, Antigravity — <…>.
Деплоер: <какая сессия выкладывает, например «сессия 04»>.
```

Строку «Лимиты» можно пропустить — тогда оркестратор спросит.

Ожидаемый результат: оркестратор пересказывает, где проект сейчас, и предлагает план: задачи, роли, инструменты и какие задачи пойдут параллельно.

## Шаг 2. Утвердить план

Прочитай план. Ответь «ок» или поправь его: «T-102 не нужна», «тестировщик через Antigravity» и т.п.

Ожидаемый результат: оркестратор пишет файлы задач, запускает все независимые задачи сразу, открываются окна исполнителей.

## Шаг 3. Не мешать

Оркестратор работает сам: следит за окнами, принимает результаты, запускает следующие задачи, переводит задачу на другой инструмент, если кончился лимит.

Окна исполнителей можно смотреть, но не закрывать: закрытое окно = оборванная задача. Окно закрывается само, когда исполнитель закончил.

Отвечай, только если просят:

- исполнитель — войти в систему или подтвердить опасное действие (прямо в его окне);
- оркестратор — решение по архитектуре, данным, деньгам;
- деплоер — «да» на прод (в его сессии).

## Шаг 4. Выкладка на сервер

Выкладку делает деплоер — та сессия, которую ты назвал на шаге 1. Оркестратор готовит задачу (`-Manual`) и даёт строку запуска, ты запускаешь её в этой сессии. Для прода деплоер сам спросит твоё «да», показав commit и окружение. Без него на прод не пойдёт. Когда закончит — `tools\run-task.ps1 T-NNN -MarkFinished`.

## Шаг 5. Закрыть день

В чате оркестратора:

```text
/update-memory
/handoff-cmd
```

Ожидаемый результат: `state/handoff.md`, `state/current-step.md` и `state/tasks.md` обновлены, `handoff.md` и `current-step.md` короткие (1–2 экрана). Сессии можно закрывать.

На следующий день — снова шаг 1. Новый оркестратор продолжит с того места, где остановился прошлый.

## Дашборд

Дашборд — твой инструмент, не агентов: таблица задач, фильтры, Гант, сроки и связи между задачами. Он только читает `state/tasks.md`, `tasks/T-*.md` и git и ничего не меняет.

1. Запусти сервер: `python dashboard\serve.py`. Он сам соберёт страницы и откроет браузер на `http://127.0.0.1:8765`. Кнопка ↻ в шапке (между «Собрано …» и темой) пересобирает обе страницы целиком и обновляет текущую.
2. Без сервера: `python dashboard\build.py`, затем открой файл `dashboard\out\index.html` (обзор) или `dashboard\out\graph.html` (Гант и сроки). Кнопка ↻ в этом режиме неактивна.
3. Дашборд обновляется только по запросу: кнопка, команда или просьба оркестратору («пересобери дашборд»). Сам он ничего не пересобирает, поэтому без запроса данные могут отставать. Страницы лежат вне git.
4. Хочешь поправить дашборд — дай задачу с описанием правки. Перед правкой: `python dashboard\snapshot.py save "что меняем"`; откат: `python dashboard\snapshot.py restore vN`. Правила интерфейса: `dashboard\UI-RULES.md`.

Интерфейс русский (он для человека); статусы реестра (`ready`, `review`, `done`…) показаны русскими метками: В очереди, На приёмке, Принята и так далее.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Исполнитель написал `blocked` | Ничего: оркестратор увидит сам. Если вопрос к тебе — он спросит |
| Кончился лимит у инструмента | Ничего: оркестратор переведёт задачу на запасной инструмент |
| Окно исполнителя закрылось | Ничего: закончил — `-Status` покажет `exited` или `error`; оборвалось — `dead`, оркестратор продолжит с последнего commit или начнёт заново |
| Исполнитель завис | Скажи оркестратору «T-101 висит». Он остановит его (`tools\run-task.ps1 T-101 -Stop`) и перезапустит |
| Оркестратор просит тебя написать «дальше» или закрыть окно | Это ошибка оркестратора: напомни про `tools\run-task.ps1 -Status` |
| Ошибка «another run-task.ps1 launch is in progress» | Подожди минуту и повтори: идёт другой запуск |
| Задача в Antigravity (IDE) или выкладка | Оркестратор готовит её (`-Manual`) и пишет папку и промпт; запускаешь ты; когда закончится — `tools\run-task.ps1 T-NNN -MarkFinished` |
| Простая задача, команда не нужна | Работай без роли: `/start-session` в начале, `/update-memory` в конце |

## Шпаргалка

| Что | Команда |
|---|---|
| Начать работу (оркестратор) | `/start-role orchestrator` + цель + лимиты + деплоер |
| Что сейчас работает | `tools\run-task.ps1 -Status` |
| Остановить зависшего исполнителя | `tools\run-task.ps1 T-NNN -Stop` |
| Запустить задачу вручную | `tools\run-task.ps1 T-NNN <codex\|claude\|agy>` |
| Таблица задач | `python tools\ledger.py show` |
| Дашборд (обзор, Гант) | `python dashboard\serve.py`, кнопка ↻ обновляет |
| Закрыть день | `/update-memory`, затем `/handoff-cmd` |
| Работа без команды | `/start-session` … `/update-memory` |
