# Инструкция: как пользоваться AgentFlow

Шаблон памяти проекта с командой агентов: оркестратор, разработчик, тестировщик, деплоер. Как это устроено внутри — [README](../README.md) и [протокол](../docs/ai-handoff-protocol.md). Здесь только «что нажать и что ввести».

Шаблон — папка, куда склонирован этот репозиторий. Ниже она обозначена `<AgentFlow>`: подставь свой путь.

Этот файл и `README.md` в проект не копируются: это инструкция к самому шаблону.

Нужно на машине: git, Python 3, PowerShell, и те CLI, которыми будут работать исполнители (`codex`, `claude`, `agy`).

# Часть 1. Установка

Выбери свой случай:

| Что в папке проекта | Вариант |
|---|---|
| Пусто, или форк / чужой код без памяти | [А. Новый проект](#а-новый-проект) |
| Уже есть память (`docs/ai-handoff-protocol.md`, `state/handoff.md`) | [Б. Проект с памятью](#б-проект-с-памятью) |

## А. Новый проект

### Шаг 1. Git

Агентам нужен git с основной веткой и хотя бы одним коммитом: разработчики работают в отдельных папках-worktree, которые создаются от основной ветки.

Пустая папка:

```powershell
cd D:\путь\к\проекту
git init -b main
```

Форк: git уже есть. Проверь имя основной ветки командой `git branch --show-current`: это `main` или `master`.

Если в проекте уже есть свои `CLAUDE.md` или `AGENTS.md`, переименуй их в `CLAUDE.old.md` / `AGENTS.old.md`. На шаге 3 Claude перенесёт из них нужное.

### Шаг 2. Скопировать шаблон

```powershell
$T = "<AgentFlow>"
Copy-Item -Path "$T\.claude", "$T\docs", "$T\roles", "$T\state", "$T\tasks", "$T\tools", "$T\AGENTS.md", "$T\CLAUDE.md" -Destination . -Recurse
Get-Content "$T\.gitignore" | Add-Content .gitignore
```

Ожидаемый результат: в проекте появились `AGENTS.md`, `CLAUDE.md`, `.claude\`, `docs\`, `roles\`, `state\`, `tasks\`, `tools\`; в `.gitignore` есть строка `tasks/.runtime/`. Проверка: `python tools/ledger.py show` выполняется без ошибки.

### Шаг 3. Заполнить память под проект

Открой папку проекта в VS Code, запусти Claude Code и введи:

```text
Внедри память в этот проект. Прочитай docs/ai-handoff-protocol.md, изучи файлы проекта
и заполни под него docs/project-plan.md, state/handoff.md, state/current-step.md.
Замени PROJECT_NAME на имя проекта. Если есть CLAUDE.old.md или AGENTS.old.md —
перенеси правила проекта в docs/engineering-rules.md и удали старые файлы.
Запиши в docs/engineering-rules.md папку для worktree: <папка вне проекта и вне OneDrive>.
Код не меняй. В конце сделай один commit.
```

Ожидаемый результат: в `docs/project-plan.md` реальные этапы проекта, в `state/handoff.md` реальное состояние, `PROJECT_NAME` нигде не осталось, есть commit.

## Б. Проект с памятью

Память уже есть: обычная, для работы в одной сессии, или командная прошлой версии. Её нужно обновить, ничего не потеряв. Вручную это делать долго и рискованно: протокол проекта мог дописываться. Поэтому переход делает Claude.

Открой проект в VS Code, запусти Claude Code и введи:

```text
Обнови AI Project Memory этого проекта до версии из шаблона
<AgentFlow> (README.md и runbook/ шаблона не копируй).
1. Скопируй то, чего в проекте нет или что в шаблоне новее: roles/, tools/, tasks/_template.md,
   state/tasks.md (только если его нет), AGENTS.md, .claude/commands/start-role.md.
   Строки из .gitignore шаблона добавь в .gitignore проекта.
2. docs/ai-handoff-protocol.md: возьми версию шаблона и перенеси в неё правила,
   которые дописывались в проекте. Список перенесённого покажи мне до записи.
3. CLAUDE.md: если это только указатель на протокол — замени шаблонным.
   Если там правила проекта — перенеси их в docs/engineering-rules.md.
4. НЕ перезаписывай: state/handoff.md, current-step, decisions, known-issues, session-log,
   state/tasks.md (если есть), docs/project-plan.md, runbook/. В decisions.md только добавь запись о переходе.
5. Правила запуска инструментов, которые лежат только в личной памяти Claude, перенеси в roles/tool-routing.md.
6. Открытые задачи из current-step или docs/work/ внеси в state/tasks.md через python tools/ledger.py.
7. Один commit.
```

Если память лежит не в корне проекта, а в соседней папке, добавь первой строкой: «Память проекта сейчас лежит в `<путь>`, перенеси её в корень проекта».

Ожидаемый результат: в проекте есть `roles/`, `tools/`, `state/tasks.md`, `AGENTS.md`. Старые handoff, decisions и known-issues на месте. Команда `/start-role` появилась в списке команд Claude Code.

## В. Один раз: проверить инструменты

Командная строка каждого CLI в `tools/run-task.ps1` (таблица `$Tools`) — значения по умолчанию. Перед первой настоящей работой проверь каждый инструмент пустяковой задачей. Качество модели не проверяется, только запуск.

1. Попроси оркестратора: «Сделай проверочную задачу T-000 для developer: прочитать README.md и записать в Result его первую строку, без коммита кода».
2. Запусти её по очереди в каждом инструменте:

```powershell
tools\run-task.ps1 T-000 codex
tools\run-task.ps1 -Status
```

После каждого прогона: `tools\run-task.ps1 T-000 -Stop`, затем следующий (`claude`, `agy`).

Для каждого инструмента должно быть:

| Проверка | Как видно |
|---|---|
| Окно открылось и видно работу | глазами |
| Prompt дошёл, роль и задача прочитаны | в окне / в `tasks\.runtime\T-000.log` |
| Рабочая папка — worktree задачи | агент пишет её в Result или видно в окне |
| `## Result` записан в `tasks\T-000-*.md` основной папки | открыть файл |
| `-Status`: `completed`, exit 0 (интерактивный `agy` — `running`, пока окно открыто) | `tools\run-task.ps1 -Status` |

Что-то не сошлось — поправь строку инструмента в `$Tools` и повтори. После проверки попроси оркестратора убрать T-000 (`cancelled`, worktree и ветку удалить).

# Часть 2. Работа каждый день

## Как это работает

```text
Ты: цель + лимиты ──> Оркестратор: план ──> Ты: «ок»
                         │
                         ▼
        Оркестратор сам, без тебя:
          запускает все задачи, которые можно делать параллельно
          следит за ними (tools\run-task.ps1 -Status)
          принимает результаты, сливает ветки
          сразу запускает следующие
                         │
                         ▼
        Ты нужен только для: входа в систему, решения по архитектуре,
        опасного действия, «да» на выкладку в прод
```

- **Оркестратор** — одна сессия Claude Code (при нехватке лимита Claude — Codex). С ним ты разговариваешь. Сам код не пишет.
- **Исполнители** — отдельные видимые окна, по одному на задачу. Их открывает оркестратор через `tools\run-task.ps1`. Ты окна не открываешь и строки запуска не вставляешь.
- Всё общение идёт через файлы: задача — `tasks/T-NNN-*.md`, результат исполнитель пишет в конец этого же файла.

## Шаг 1. Запустить оркестратора

VS Code → открыть папку проекта → новая сессия Claude Code → ввести:

```text
/start-role orchestrator
Цель: <что хочешь получить>.
Лимиты: Claude — <много/мало>, Codex — <…>, Antigravity — <…>.
Деплоер: <какая сессия выкладывает, например «сессия 04»>.
```

Строку «Лимиты» можно пропустить — тогда оркестратор спросит.

Ожидаемый результат: оркестратор пересказывает, где проект сейчас, и предлагает план: задачи, роли, инструменты и какие задачи пойдут параллельно.

## Шаг 2. Утвердить план

Прочитай план. Ответь «ок» или поправь его: «T-102 не нужна», «тестировщик через Antigravity» и т.п.

Ожидаемый результат: оркестратор пишет файлы задач, запускает все независимые задачи сразу, открываются окна исполнителей.

## Шаг 3. Не мешать

Оркестратор работает сам: следит за окнами, принимает результаты, запускает следующие задачи, переводит задачу на другой инструмент, если кончился лимит.

Окна исполнителей можно смотреть, но не закрывать: закрытое окно = оборванная задача. Окно, где написано «You can close this window», закрыть можно.

Отвечай, только если просят:

- исполнитель — войти в систему или подтвердить опасное действие (прямо в его окне);
- оркестратор — решение по архитектуре, данным, деньгам, или «да» на прод.

## Шаг 4. Выкладка на сервер

Выкладку делает деплоер — та сессия, которую ты назвал на шаге 1. Оркестратор готовит задачу, ты запускаешь её в этой сессии. Для прода оркестратор спросит твоё «да». Без него деплоер на прод не пойдёт.

## Шаг 5. Закрыть день

В чате оркестратора:

```text
/update-memory
/handoff-cmd
```

Ожидаемый результат: `state/handoff.md`, `state/current-step.md` и `state/tasks.md` обновлены, `handoff.md` и `current-step.md` короткие (1–2 экрана). Сессии можно закрывать.

На следующий день — снова шаг 1. Новый оркестратор продолжит с того места, где остановился прошлый.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Исполнитель написал `blocked` | Ничего: оркестратор увидит сам. Если вопрос к тебе — он спросит |
| Кончился лимит у инструмента | Ничего: оркестратор переведёт задачу на запасной инструмент |
| Окно исполнителя закрылось само | Ничего: `-Status` покажет `dead`, оркестратор продолжит с последнего commit или начнёт заново |
| Исполнитель завис | Скажи оркестратору «T-101 висит». Он остановит его (`tools\run-task.ps1 T-101 -Stop`) и перезапустит |
| Оркестратор просит тебя написать «дальше» или закрыть окно | Это ошибка оркестратора: напомни про `tools\run-task.ps1 -Status` |
| Ошибка «is being launched by another run-task.ps1» | Подожди минуту и проверь `-Status`: запуск этой задачи уже идёт |
| Задача в Antigravity (IDE) | Её запускаешь ты вручную; когда закончится, `tools\run-task.ps1 T-NNN -MarkFinished` |
| Простая задача, команда не нужна | Работай без роли: `/start-session` в начале, `/update-memory` в конце |

## Шпаргалка

| Что | Команда |
|---|---|
| Начать работу (оркестратор) | `/start-role orchestrator` + цель + лимиты + деплоер |
| Что сейчас работает | `tools\run-task.ps1 -Status` |
| Остановить зависшего исполнителя | `tools\run-task.ps1 T-NNN -Stop` |
| Запустить задачу вручную | `tools\run-task.ps1 T-NNN <codex\|claude\|agy>` |
| Таблица задач | `python tools\ledger.py show` |
| Закрыть день | `/update-memory`, затем `/handoff-cmd` |
| Работа без команды | `/start-session` … `/update-memory` |
